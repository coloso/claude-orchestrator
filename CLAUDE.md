# Project rules (read by every agent)

This repo is built by several Claude agents in parallel.
Each agent works in its own git worktree on one task.

## Layout
- `backend/` — Go 1.27 API. Spec-first with [ogen](https://ogen.dev).
  - `api/openapi.yaml` — **the single source of truth for the HTTP API** (OpenAPI 3.0)
  - `internal/oas/` — code generated by ogen from the spec. **Never edit by hand**; run `go generate ./...`
  - `internal/handler/` — `Handler` implements `oas.Handler` by embedding one service per feature
  - `internal/<feature>/` — feature services (e.g. `internal/todos`), with `_test.go` files next to the code
  - `internal/apperr/` — errors with HTTP status (`apperr.NotFound`, `apperr.BadRequest`)
  - `internal/server/` — builds the root `http.Handler` (ogen server + error rendering + middleware)
  - `cmd/server/` — entry point (`go run ./cmd/server`, listens on :8000)
  - `e2e/` — end-to-end tests against `server.New()` using the generated `oas.Client`
- `frontend/` — reserved for a Vue 3 + TypeScript app (not set up yet)
- `docs/` — Markdown documentation
- `orchestration/` — the tooling that runs you (orchestrator, roles, plans, dashboard). **Never modify it.**

## Rules
- Only create or modify files inside the scope listed in your task. Changes outside it are rejected.
- Do not run `git commit`, `git checkout`, or other branch operations. The orchestrator commits for you.
- Keep changes small and focused on your task. No new Go modules unless the task says so.
- Before finishing, run `backend/check.sh` (go generate drift check, gofmt, go vet, go test). It must pass.

## How an API change flows
1. Change `backend/api/openapi.yaml`, then `cd backend && go generate ./...`.
   New operations compile immediately and return 501 until a service implements them.
2. Implement the operations in a feature service whose methods match the generated `oas.Handler`
   signatures, and embed the service in `handler.Handler` (see `internal/handler/handler.go`).
3. Return `apperr.*` errors for 4xx cases; `Handler.NewError` renders them as `{"error": "..."}`.

## API conventions
- All routes are prefixed with `/api`, JSON in and out.
- Every operation declares only its success response plus `default: $ref: '#/components/responses/Error'`.
  Don't declare explicit 4xx responses: ogen then generates per-operation union types (`GetTodoRes`) and
  errors bypass `apperr`. Mention possible error statuses in the operation `description` instead.
- Use `operationId` in camelCase (`listTodos`, `createTodo`); ogen derives Go method names from it.
