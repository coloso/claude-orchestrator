# Project rules (read by every agent)

This repo is built by several Claude agents in parallel.
Each agent works in its own git worktree on one task.

## Architecture

The backend is a Go 1.27 API built spec-first with [ogen](https://ogen.dev), using **DDD + hexagonal architecture**.
Every feature is a bounded context, and every bounded context is a hexagon:

```
backend/
├── api/openapi.yaml          the API contract, single source of truth
├── internal/
│   ├── <context>/            one bounded context, e.g. todo/
│   │   ├── domain/             aggregates, value objects, domain errors, repository interface. Pure Go
│   │   ├── app/                UseCases interface (inbound port) + Service
│   │   └── adapter/
│   │       ├── httpapi/        driving adapter: implements the context's oas.Handler methods
│   │       ├── mongodb/        driven adapter: MongoDB domain.Repository
│   │       └── repotest/       repository contract suite, run against the MongoDB repository
│   ├── oas/                  generated by ogen. Never edit by hand
│   ├── handler/              embeds every context's httpapi adapter → oas.Handler (501 fallback)
│   ├── server/               ogen server, transport error rendering, middleware
│   ├── middleware/           HTTP middleware
│   ├── platform/mongodb/     MongoDB connection (shared infrastructure for adapters)
│   ├── bootstrap/            composition root: connects to MongoDB, migrates, wires repositories → services → adapters
│   └── archtest/             dependency rules, enforced by go test. Never modify
├── cmd/server/               entry point (:8000), config from env, graceful shutdown, -healthcheck
├── Dockerfile                distroless image, used by ../docker-compose.yml
├── e2e/                      tests against bootstrap.New() via the generated oas.Client (security_*_test.go: security regressions)
└── check.sh                  all checks; must pass before you finish
```

Dependency rules (enforced by `internal/archtest`):
- Dependencies point inwards: adapter → app → domain.
- `domain` and `app` must not use `oas`, `net/http`, `encoding/json`, `database/sql` or third-party modules.
- Bounded contexts never import each other.
- Only `internal/handler` (for httpapi adapters) and `internal/bootstrap` may import a context.

## Storage
- MongoDB 8 via `docker-compose.yml` at the repo root (`docker compose up`).
- `bootstrap.ConfigFromEnv` reads `MONGO_URI` (default `mongodb://localhost:27017`), `MONGO_DB` (default `orch`) and `SEED_DEMO_DATA`. There is no storage setting; `STORAGE` is ignored.
- The server always connects to MongoDB and migrates before serving. If MongoDB is unreachable, it exits with an error that names the URI without credentials.
- Tests need MongoDB: `make mongo`, then `export MONGO_TEST_URI=mongodb://localhost:27017`. `backend/check.sh` fails at the start without it.
  Every test that needs storage runs on its own test database, which is dropped when the test ends, because parallel agents may share one server.
  e2e tests get theirs from the shared helper in `backend/e2e/e2e_test.go` (`e2eStart`, `e2eMongoConfig`).
- Domain and app unit tests use test doubles in their own `_test.go` files. The `adapter/repotest` contract suite runs against the MongoDB repository.

Schema changes are migrations. Each bounded context exposes `Migrations()` in `internal/<context>/adapter/mongodb`, and `bootstrap.migrationSets()` lists them. Migrations are forward-only and numbered `<context>/<NNNN>` from 0001 with no gaps. Never edit an applied migration; fix mistakes with a new one. An `Up` step must be idempotent, because it reruns if recording fails. Use `platformmongo.EnsureCollection` and `EnsureIndexes`, and build schemas with bson.D. Use int64 for `long` fields and int for `int` fields. See docs/schema-migrations.md for the full rules and the operations guide.

Other folders:
- `frontend/` — reserved for a Vue 3 + TypeScript app (not set up yet)
- `docs/` — Markdown documentation; `docs/security/` holds security review reports
- `backlog/` — stories and plans, written by humans. **Never modify it.**
- `orchestration/` — the tooling that runs you (orchestrator, roles, dashboard). **Never modify it.**

## Rules
- Only create or modify files inside the scope listed in your task. Changes outside it are rejected.
- Do not run `git commit`, `git checkout`, or other branch operations. The orchestrator commits for you.
- Keep changes small and focused on your task. No new Go modules unless the task says so.
- Domain and application code is written **test-first** (red → green → refactor).
  - The gate rejects `domain`/`app` changes that come without test changes in the same package.
  - It also requires at least 80% coverage in those layers.
- Migrations are part of a context's adapter/mongodb package and are tested against MongoDB (`MONGO_TEST_URI`).
- Before finishing, run `backend/check.sh`: generate drift check, gofmt, vet, tests (including archtest), coverage, gosec and govulncheck. It must pass.
- **Work outside your scope:** don't do it. Propose it instead.
  - Write a JSON array of follow-up tasks to `.orch-proposals.json` at the worktree root. Each entry has `title`, `role`, `prompt` and `scope`, plus optional `depends_on` (existing task IDs, or titles of other proposals in the same file), `model` (`haiku`, `sonnet` or `opus`), `effort` (`low` … `xhigh`), `severity` and `rationale`.
  - The file is never committed. A human reviews the proposals and approves or rejects them.

## How a feature flows
1. **Spec:** change `backend/api/openapi.yaml`, then `cd backend && go generate ./...`. New operations compile immediately and return 501.
2. **Model** (can run in parallel with step 1): test-first domain, then use cases, then the MongoDB repository in `adapter/mongodb`, checked by `adapter/repotest`.
3. **HTTP adapter:**
   - write `adapter/httpapi` against `app.UseCases`, mapping oas ↔ domain and domain errors → `*oas.ErrorStatusCode`;
   - embed it in `handler.Handler`;
   - construct it in `bootstrap.New()`.
4. **e2e:** test the wired app through the generated client, on a fresh MongoDB test database.

## API conventions
- All routes are prefixed with `/api`, JSON in and out.
- Every operation declares only its success response plus `default: $ref: '#/components/responses/Error'`.
  - Don't declare explicit 4xx responses: ogen would then generate per-operation union types (`GetTodoRes`).
  - Mention the possible error statuses in the operation `description` instead.
- `operationId` in camelCase (`listTodos`); ogen derives Go method names from it. One `tag` per bounded context.
- Errors are `{"error": "<message>"}`. Adapters map domain errors; anything unmapped becomes a 500.
