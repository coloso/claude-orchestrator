# S02-02.6: Security review of the books implementation (S-02)

Reviewed after the catalog HTTP adapter, the MongoDB repository, the bootstrap wiring and the fixes proposed in [S02-02-books-api-spec.md](S02-02-books-api-spec.md) landed. Date: 2026-10-25. Reviewer role: security.

## Scope reviewed

- API contract: `backend/api/openapi.yaml` (after `S02-02.1`).
- HTTP layer: `internal/server/server.go` (body limit, security headers, transport error rendering), `internal/middleware/ratelimit.go`, `cmd/server/main.go` (`newHTTPServer`), `internal/handler/handler.go` (`NewError`, `GetHealth`).
- Catalog: `internal/catalog/domain` (validation), `internal/catalog/app/service.go`, `internal/catalog/adapter/httpapi/handler.go` (error mapping), `internal/catalog/adapter/mongodb/repository.go` and `migrations.go`.
- Wiring and infrastructure: `internal/bootstrap/bootstrap.go`, `internal/platform/mongodb/mongodb.go`, `docker-compose.yml`, `backend/Dockerfile`, `backend/.dockerignore`.
- Tool output: `backend/check.sh` (`gosec`: no issues, no `#nosec` in non-generated code; `govulncheck`: see "Checked and fine").
- Not reviewed: the frontend (does not exist yet), `orchestration/`, `backlog/`.

### How the findings were verified

- `backend/e2e/security_books_test.go` sends raw `net/http` requests to the fully wired app (`bootstrap.New`), once on the memory repository and once on MongoDB 8.0 (the compose `mongo` service; the Mongo variants run only when `MONGO_TEST_URI` is set, as with the other storage tests). Both variants passed here, also with `-race`.
- The one test that does not hold yet (`TestSecurityBooksMongoOperationsHaveATimeout`, SEC-S02-9) was run un-skipped to confirm it fails today, then re-skipped.
- Unit-level behavior (rate limiter, server timeouts) is covered by the existing tests of `internal/middleware`, `internal/server` and `cmd/server`; I read them rather than duplicating them.

## Accepted risks

| Risk | Why accepted |
|---|---|
| **No authentication or authorization** (stated once here, not repeated per finding) | The demo has no users. Anyone who can reach the port can create, change and hard-delete any book. |
| Plain HTTP, no TLS | Local demo. A TLS-terminating proxy is needed before any real deployment. |
| Enumeration of book IDs and ISBNs; hard delete with no audit trail | Product decision (S-02). Sequential IDs and the open list endpoint make 404/409 differences uninteresting. |
| No cap on the number of books | Product decision. The rate limiter bounds growth per client (5 writes/s sustained, burst 20), not in total. |
| Loopback clients are exempt from rate limiting (`server.go:35`) | The e2e tests and local tooling connect that way. Documented in the code. It becomes a bypass if a reverse proxy runs on the same host: every user of that proxy is then "loopback". The deployment note: rate limit in the proxy, or change `ExemptLoopback` first. |
| `X-Forwarded-For` is ignored by the rate limiter | Correct (client-controlled). Behind a proxy all users share one bucket, which fails closed. |

## Threat model

**Assets**: availability of the API and MongoDB (CPU, memory, connections, disk); integrity of the catalog (ISBN uniqueness, the `version` counter, `$jsonSchema` invariants); the process (no crash, no internal details in responses or logs).

**Entry points**: `POST/GET /api/books`, `GET/PUT/DELETE /api/books/{id}`, `GET /api/health`. Untrusted: JSON bodies, `author`/`limit`/`offset` query parameters, path `id`, `Content-Type`, `Content-Length`/chunking, header size, connection behavior (slow clients), source address.

**Trust boundaries**: network → server middleware (headers, rate limit, body limit) → ogen decoder/validator → catalog HTTP adapter → app/domain (real validation) → repository → MongoDB (second line: `$jsonSchema`, unique index). Operator-controlled: environment (`MONGO_URI`, `SEED_DEMO_DATA`), `docker-compose.yml`.

| STRIDE | Threat | Result |
|---|---|---|
| **S**poofing | Out of scope (no auth). Spoofed `X-Forwarded-For` to dodge the rate limiter. | Header ignored (tested in `middleware`). |
| **T**ampering | Mass assignment of `id`/`version`/`createdAt`/`updatedAt`; NoSQL operator injection through `author` or author names; lost updates; writes to MongoDB without credentials. | First three: fixed, pinned. Last: SEC-S02-11. |
| **R**epudiation | No audit log. | Accepted with the auth risk. |
| **I**nformation disclosure | Library, driver or Go text in responses and logs; request bodies in logs; missing `nosniff`/`no-store`/CSP; open CORS. | Fixed, pinned. Nothing found. |
| **D**enial of service | Large/slow bodies, huge arrays, deep nesting, deep `skip`, slow `count`, stalled database, unlimited write rate, source-address rotation, health endpoint. | Body, nesting, `skip`: fixed, pinned. Stalled database: SEC-S02-9. Count: SEC-S02-10. Rate limit gaps: SEC-S02-12. |
| **E**levation of privilege | Not applicable (no privileges). Container breakout surface. | SEC-S02-13 (hardening). |

| SEC-S02-9 | No deadline on any MongoDB operation | medium | `internal/catalog/adapter/mongodb/repository.go:88,104,129,144,148,169,188`; `internal/platform/mongodb/mongodb.go:19` (client has only a 5 s server-selection timeout, no `Timeout`) | When MongoDB stops answering without closing the connection (network partition, overloaded or paused server), every request blocks until the HTTP client disconnects. ### SEC-S02-9 in more detail

`bootstrap.New` hands each context a `*mongo.Database` from `platformmongo.Connect`, whose client options set `ServerSelectionTimeout(5s)` only. Every repository method passes the request context straight to the driver, and an HTTP request context ends only when the client goes away or the server shuts down. The three observed outcomes with the database frozen:

1. A request whose connection is already pooled waits for a reply forever (the test client gave up after 15 s; the server-side error `incomplete read of message header: context canceled` then shows the client's cancellation was the only thing that ended it).
2. A request that needs a new connection fails after 5 s (`timed out while checking out a connection ... wait duration: 5s`), because the server-selection timeout also bounds checkout.
3. `GET /api/health` is unaffected in the sense that it has its own 2 s deadline, so the container health check reports the outage correctly while normal requests hang.

Note for the fix: the client-wide `SetTimeout` (CSOT) also applies to the migration helpers, which build indexes on possibly large collections. Prefer per-call `context.WithTimeout` in the catalog repository, or check the migrations before choosing the client-wide option.

## Notes from the spec review: results

| Note (from S02-02) | Result |
|---|---|
| Unmapped repository errors become a generic 500 | **Holds.** `httpapi.mapError` returns unknown errors unchanged; ogen passes them to `Handler.NewError` (`handler.go:46`), which logs them and answers `{"error":"internal server error"}`. Pinned: after the Mongo client is disconnected, get/list/create/update/delete all return exactly that body (`TestSecurityBooksUnmappedRepositoryErrorsBecomeAGeneric500`). |
| E11000 on `isbn` maps to 409 without driver text | **Holds** (message match is fragile: SEC-S02-14). `isDuplicateISBN` only accepts code 11000 on `isbn_unique`; a duplicate `_id` is a 500 on purpose. `mapError` answers with the fixed sentinel text, never the wrapped error. Pinned for POST, PUT, hyphenated ISBN variants and 12 racing creates, on both repositories. |
| User input never becomes a `bson` key or `$` operator | **Holds.** The only user-controlled value in a filter is `bson.D{{Key: "authors", Value: f.Author}}`, a Go `string` (`repository.go:141-143`); `isbn`, `_id` and `version` filters come from typed values (`ISBN`, `int64`). Writes go through the `bookDoc` struct. Pinned: `author=%24ne`, `{"$ne":"x"}` as text, `.*`, `Ali`, `author[$ne]=x`, `author=Alice&author[$ne]=Alice`, and authors named `$ne`, `{"$gt":""}`, `$where: sleep(1000)` all behave as plain text on MongoDB. |
| Every Mongo call has a context timeout | **Does not hold**: SEC-S02-9. |
| Unfiltered total uses a deliberate count strategy | **Not documented**: SEC-S02-10. |
| No request bodies in logs | **Holds.** `server.writeError` logs the ogen error at DEBUG, and its text carries the operation, the field name and a position, not values (`decode field "publishedYear": unexpected byte 34 '"' at 71`). Observed at DEBUG: unknown field names and bad query/path values (`strconv.Atoi: parsing "..."`, up to the 16 KiB header limit) are logged, but never body values. The raw body in ogen's `DecodeBodyError` is not printed because `err` is logged with `%v`, not `%+v`. Pinned with a marker in 11 kinds of bad bodies at DEBUG level (`TestSecurityBooksRequestBodiesAreNeverLogged`), and the test fails if the capture saw no transport error at all. |
| Seeding not reachable from the API | **Holds.** `SeedDemo` is called only in `bootstrap.New` when `Config.SeedDemoData` is set, and `SEED_DEMO_DATA` is read from the environment. No route calls it, and the list is empty by default. Pinned with 11 guessed paths and 3 methods. |

## Checked and fine

| Check | Result |
|---|---|
| `govulncheck` | No vulnerability in called code or imported packages. One module-level advisory, GO-2026-5932 (`golang.org/x/crypto/openpgp`, no fix), comes in through the MongoDB driver's `x/crypto` dependency; nothing imports `openpgp`. Re-check when `x/crypto` is bumped. |
| `gosec` | No issues; no suppressions in hand-written code. |
| Body handling | `r.ContentLength` is checked up front and `MaxBytesReader` caps chunked bodies; the 413 path is the same for both. Rate limiting runs before the body limit, so oversized writes still use a token. |
| Response sizes | Error bodies ≤ 512 bytes in all probes. The only echo of input is the 404 for an unknown route (`no route for GET /path`, JSON-escaped, bounded by the 16 KiB header limit, `nosniff` + JSON content type). |
| CSRF / drive-by writes | Non-JSON content types → 415 before decoding (`text/plain`, form, multipart tested: nothing stored). `PUT`/`DELETE` need a CORS preflight, and no CORS header is ever sent. Keep that when the frontend arrives. |
| Integer handling | `version`, `id`, `total`, counter: `int64`; `publishedYear`, `pages`, `limit`, `offset`: `int`. No wrap-around: 20-digit and 2^63 values → 400. |
| Optimistic locking | `ReplaceOne` filters on `{_id, version}`; a miss is followed by a `Get` to tell 404 from 409. Concurrent updates covered by the existing storage e2e test. |
| Mongo queries | All filters are `bson.D` built from typed values. No `bson.M`, no `$where`, no raw command. `sort` is fixed (`_id`); `limit` ≤ 100; `skip` ≤ 100000. |
| Second line of defense | `$jsonSchema` + unique `isbn` index. The schema `pattern` for `language` accepts `en\n` in PCRE, so the domain check stays authoritative (it is, and is pinned). |
| ID counter | `FindOneAndUpdate` with `$inc` is atomic; the first-call race is retried once. A failed insert burns an ID (a gap, no leak). |
| Docker image | Distroless `static:nonroot`, `CGO_ENABLED=0`, no shell, no secrets, `.dockerignore` is an allow-list that also excludes tests. Ports published on `127.0.0.1` only. Both services have health checks. |
| Config | `STORAGE`, `MONGO_URI`, `MONGO_DB`, `SEED_DEMO_DATA` come from the environment; none is logged (only `storage` is). No credential appears in the repo. |
